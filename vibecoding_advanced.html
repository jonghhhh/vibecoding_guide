0부. 5분 만에 잡는 큰 그림

0-1. 오늘 배울 것을 한 문장으로

입문에서는 "말로 시켜서 만들었다"면, 심화에서는 "내가 매번 설명하지 않아도 AI가 알아서 하게 만든다"입니다.

같은 지시를 매번 타이핑하는 대신, 규칙은 파일로 고정하고, 반복 작업은 명령으로 저장하고, 큰일은 다른 일꾼에게 떼어 맡기고, 외부 도구는 선을 연결해 둡니다.

0-2. 7개 부품 — 비유로 한 번에

부품 비유 한 줄 설명
① 슬래시 명령어 리모컨 버튼 내가 눌러서 세션을 조종합니다 (/model, /clear …)
② 메모리 파일 신입에게 주는 업무 매뉴얼 매 세션 자동으로 읽힙니다 (CLAUDE.md, AGENTS.md)
③ 커스텀 명령어 내가 만든 나만의 리모컨 버튼 자주 쓰는 긴 프롬프트를 /한단어로 저장
④ 스킬(Skill) 상황 보고 알아서 꺼내 쓰는 전문 매뉴얼 AI가 맥락을 보고 스스로 발동
⑤ 서브에이전트 일을 떼어 맡기는 별도 직원 자기 책상(독립 문맥)을 따로 씁니다
⑥ 훅(Hook) "이 일 끝나면 자동으로 ○○해" 알람 특정 순간에 내 스크립트를 자동 실행
⑦ MCP 외부 회사와 연결하는 전용 전화선 깃허브·DB·노션 등을 AI에 연결

이 특강의 중심은 ② 메모리 파일 · ④ 스킬 · ⑤ 서브에이전트 셋입니다 — 각각 3장 · 5장 · 6장에서 다룹니다. 나머지 넷은 이름만 알아 두고, 필요해질 때 해당 장을 찾아보세요.

curl -fsSL https://claude.ai/install.sh | bash

# OpenAI Codex — macOS · Linux

npm을 선호한다면 npm i -g @anthropic-ai/claude-code, npm i -g @openai/codex도 됩니다. Antigravity CLI는 npm 패키지가 없습니다 — 설치 스크립트만 씁니다.

1장. 슬래시 명령어의 기본기 (3도구 공통)

1-1. 슬래시 명령어란?

세션 입력창에 / 를 치면 뜨는 조종 명령입니다. AI에게 보내는 일반 프롬프트와 달리, 세션 자체(모델 변경·문맥 정리·승인 설정 등)를 다룹니다.

  • 입력창에 / 를 치면 명령 목록 팝업이 뜹니다. 계속 타이핑하면 필터링됩니다.
  • 세 도구 모두 /help 로 현재 버전에서 쓸 수 있는 전체 목록을 볼 수 있습니다. 버전이 자주 바뀌므로 이게 가장 확실한 방법입니다.

1-2. 슬래시와 함께 쓰는 두 기호: @ 와 !

기호 뜻 예시
/ 세션 조종 /model, /clear
@ 파일·폴더를 프롬프트에 첨부 @src/main.py 이 파일 설명해 줘
! 셸 명령 바로 실행(AI를 거치지 않음) !git status

이 3개만 알아도 절반은 끝납니다. 슬래시는 리모컨, 골뱅이는 맥락 첨부, 느낌표는 터미널 직접 실행입니다.

2장. 도구별 핵심 내장 슬래시 명령어

도구마다 명령이 수십 개지만, 실제로 자주 쓰는 것만 추렸습니다. 전체 목록은 /help를 보세요.

2-1. Claude Code (90개 이상 중 핵심)

명령 하는 일
/help 전체 명령 목록
/init 프로젝트를 분석해 CLAUDE.md 자동 생성
/model 모델 변경 (Opus 5 / Sonnet 5 / Haiku 4.5 등)
/effort 추론 '노력 수준' 조절 (low·medium·high·xhigh·max, 기본 high)
/context 현재 문맥(컨텍스트) 사용량 확인
/compact 긴 대화를 요약해 문맥 공간 확보
/clear 대화 내용 초기화(새 작업 시작)
/memory CLAUDE.md 등 메모리 파일 편집
/review 변경 코드 리뷰 요청
/agents 서브에이전트 보기·생성·관리
/mcp MCP 서버 연결 상태 관리
/hooks 훅 설정 보기·관리
/plugin 플러그인 마켓플레이스·설치
/resume 이전 세션 이어서 하기
/cost 이번 세션 토큰·비용 확인
/doctor 설치 상태 점검

플랜 모드: Shift+Tab 으로 모드를 순환하면 계획만 세우고 실행은 멈추는 플랜 모드로 들어갑니다. 큰 작업 전 안전장치입니다.

effort(노력 수준): /effort는 Claude가 얼마나 깊이 생각할지를 정하는 다이얼입니다(출력 길이가 아니라 '사고 깊이'를 조절합니다). 단순·대량 작업은 low, 기본은 high, 복잡한 코딩·에이전트 작업은 xhigh, 가장 깊게는 max. 무조건 높인다고 좋은 게 아니라 과제 난이도에 맞춰 씁니다.

2-2. OpenAI Codex (60개 이상 중 핵심)

명령 하는 일
/help 전체 명령 목록
/init AGENTS.md 골격 자동 생성
/model 모델 변경 (GPT-5.6 Sol / Terra / Luna)
/plan 읽기 전용 플랜 모드(실행 없이 계획)
/review 작업 트리 리뷰(동작 변화·누락 테스트 중심)
/diff 바뀐 파일 차이 보기
/mcp MCP 도구 목록 (/mcp verbose로 상세 진단)
/skills 사용 가능한 스킬 보기 ($로 직접 호출)
/apps 연결된 앱을 $앱-이름으로 삽입
/plugins 플러그인 마켓 탐색·설치
/hooks 훅 관리
/status 현재 모델·권한·문맥 상태. 예상 크레딧·비용도 표시
/cd · /pwd · /cwd 작업 디렉터리 확인·변경
/export 대화 전체를 마크다운으로 내보내기
/compact 긴 세션 요약
/clear · /resume 새 대화 시작 / 이어서 하기

샌드박스(권한) 모드: read-only(읽기) → workspace-write(작업 폴더 쓰기) → danger-full-access/--yolo(전체 허용). --yolo는 승인·보호를 모두 끄므로 격리 환경에서만 쓰세요. Alt+, / Alt+. 로 추론(reasoning) 깊이를 낮추거나 높일 수 있습니다.

모델 정리(2026.8) — 현재 권장 모델은 GPT-5.6 Sol(최고 성능) · Terra(균형) · Luna(빠르고 저렴)입니다. 옛 자료의 gpt-5.3-codex·gpt-5.2는 ChatGPT 계정 기준으로 이미 중단됐고, gpt-5.4는 2026년 8월 31일 종료됩니다. 설정 파일에 모델을 고정해 뒀다면 gpt-5.6-terra·gpt-5.6-luna로 바꾸세요.

터미널 밖 기능: codex agents(대시보드), codex queue(실행 중 세션에 메시지 보내기), codex exec fork(세션 분기)도 최근 추가됐습니다.

2-3. Antigravity CLI (agy) 핵심

구 Gemini CLI의 후속입니다. 실행 명령이 gemini → agy로 바뀌었고 설정 경로·명령 체계도 함께 달라졌습니다.

명령 하는 일
/usage (= /quota) 남은 사용량 확인. 무료 한도가 빡빡해 수시 확인이 필요합니다
/credits 남은 AI 크레딧 확인
/config (= /settings) 설정 확인·변경
/permissions 도구 승인 규칙 확인·변경
/diff 바뀐 파일 차이 보기
/skills 사용 가능한 스킬 목록
/agents · /tasks 서브에이전트 실행·진행 상황 모니터링
/mcp MCP 서버 관리 화면 열기
/codesearch 코드베이스 검색
/artifact 산출물(아티팩트) 검토 패널
/clear (= /new) 새 대화 시작
/resume (= /switch, /conversation) 이전 대화 이어서 하기

승인 모드 — toolPermission 값 4가지

설정 파일(~/.gemini/antigravity-cli/settings.json)이나 /permissions에서 바꿉니다.

값 동작 언제
request-review 쓰기·터미널·웹 도구 실행 전 승인 요청 기본값
strict 읽기 외 모든 도구에 승인 요청 가장 조심스러울 때
proceed-in-sandbox 샌드박스 안 명령은 자동 실행, 나머지는 승인 요청 익숙해진 뒤
always-proceed 아무것도 묻지 않고 실행 격리 환경에서만

권한 규칙은 read_file·write_file·read_url·command·mcp 등 동작 단위로 deny / ask / allow를 지정하며, 충돌하면 deny > ask > allow 순으로 강한 쪽이 이깁니다.

사용량 주의 — 무료 등급은 하루 20회 안팎의 에이전트 요청으로 제한됩니다(5시간 단위 회복). 유료 등급도 2026년 3월부터 주 단위 한도로 바뀌어, 한도를 소진하면 최대 일주일간 잠길 수 있습니다. 특히 서브에이전트를 병렬로 돌리면 사용량이 급격히 소모되므로, 9장의 병렬 기법은 유료 등급에서만 시도하세요.

3장. 메모리 파일 — CLAUDE.md · AGENTS.md

한 줄 요약: AI에게 주는 업무 매뉴얼입니다. 매 세션 자동으로 읽히므로, 프로젝트 설명을 반복할 필요가 없어집니다.

3-1. 왜 가장 중요한가?

  • 이 파일이 AI의 헌법입니다. 매 세션 자동으로 읽혀 같은 설명을 반복하지 않아도 됩니다.
  • 고급 기능을 건드리기 전에 이 파일부터 제대로 써야 효과가 큽니다.
  • 세 도구 모두 /init으로 초안을 자동 생성할 수 있습니다. 먼저 만들고 다듬는 편이 빠릅니다.
  • 위치는 프로젝트 폴더 최상단입니다. 모든 프로젝트에 공통 적용할 규칙은 각 도구의 홈 디렉터리에 둡니다.

3-2. 스킬·서브에이전트는 어떻게 '알아서' 발동하나

5장 스킬과 6장 서브에이전트는 둘 다 내가 부르지 않아도 AI가 맥락을 보고 스스로 꺼내 씁니다. 그러려면 두 가지가 갖춰져야 합니다.

단계 무엇이 필요한가 어디에
① 등록 파일이 정해진 폴더에 있어야 AI가 존재를 압니다 스킬 .claude/skills/<이름>/SKILL.md
서브에이전트 .claude/agents/<이름>.md
② 판단 AI는 파일 머리말의 description 한 줄을 보고 "지금 쓸까"를 정합니다 파일 맨 위 --- 사이 (= 프론트매터)

description이 전부입니다. AI는 평소 본문을 읽지 않습니다. 이름과 description만 목록으로 갖고 있다가, 필요해 보일 때 그 파일을 열어 봅니다. 그래서 "관광 관련 작업" 같은 두루뭉술한 설명이면 영영 안 불립니다. "언제 쓰는지"를 문장으로 쓰세요.

메모리 파일은 '등록하는 곳'이 아니라 '발동을 못박는 곳'입니다.

CLAUDE.md에 적는다고 스킬·서브에이전트가 등록되지는 않습니다 — 등록은 ①의 폴더가 합니다. 대신 "이럴 땐 이걸 써라"는 규칙을 적어 두면 발동이 훨씬 안정적으로 걸립니다. description만으로는 AI가 놓칠 때가 있는데, 메모리 파일은 매 세션 자동으로 읽히므로 그 빈틈을 메웁니다. 실제 문장은 다음 절 예시의 # 스킬·서브에이전트 사용 규칙 항목을 보세요.

정리 — 폴더가 "무엇이 있는지", description이 "언제 쓰는지", 메모리 파일이 "그래도 놓치지 마라"를 담당합니다. 셋이 함께 있을 때 자동 발동이 제대로 걸립니다.

3-3. 작성 예시 (도구가 달라도 내용은 거의 동일)

# 프로젝트 개요
이 저장소는 미디어학과 수업용 뉴스 분석 파이썬 프로젝트다.

# 코딩 규칙
- 모든 주석과 설명은 한국어로 작성한다.
- 의존성은 requirements.txt에 명시하고, 불필요한 라이브러리는 추가하지 않는다.
- 함수에는 한 줄 설명을 단다.

# 스킬·서브에이전트 사용 규칙
- 코드 리뷰를 요청하면 reviewer 서브에이전트(.claude/agents/reviewer.md)에게 맡긴다.
- 뉴스 CSV를 정리하는 작업이면 news-cleaner 스킬(.claude/skills/news-cleaner/)을 먼저 읽는다.
- 자료 조사처럼 오래 걸리는 일은 서브에이전트에 떼어 맡기고, 요약만 받는다.

# 자주 쓰는 명령
- 테스트:  pytest
- 실행:    python main.py

# 하지 말 것
- .env 파일을 절대 커밋하지 않는다.
- 대규모 리팩터링은 먼저 계획을 보여주고 승인받는다.
도구 파일명 전역(글로벌) 위치 초안 생성
Claude Code CLAUDE.md ~/.claude/CLAUDE.md /init
OpenAI Codex AGENTS.md ~/.codex/AGENTS.md /init
Antigravity CLI AGENTS.md (여러 개면 .agents/rules/*.md) ~/.gemini/antigravity-cli/ /config에서 확인

작성 팁 — 규칙은 짧고 명령형으로 쓰세요. "되도록 깔끔하게" 같은 모호한 말보다 "함수는 30줄을 넘기지 말 것"처럼 검증 가능한 규칙이 훨씬 잘 지켜집니다.

4장. 커스텀 슬래시 명령어 만들기

한 줄 요약: 자주 쓰는 긴 프롬프트를 /한단어로 저장합니다. 예: /리뷰, /한글주석, /커밋메시지.

4-1. Claude Code

.claude/commands/ 폴더에 .md 파일을 만들면 파일명이 곧 명령이 됩니다.

mkdir -p .claude/commands
cat > .claude/commands/한글주석.md << 'EOF'
방금 작성한 코드에 초보자가 이해하기 쉬운 한국어 주석을 충분히 달아 줘.
대상 파일: $ARGUMENTS
EOF

→ 이제 /한글주석 src/main.py 처럼 씁니다. ($ARGUMENTS=전체 인자, $1 $2=위치 인자)

4-2. OpenAI Codex

~/.codex/prompts/ 폴더에 최상위 .md 파일을 둡니다. (하위 폴더는 인식하지 않습니다.)

mkdir -p ~/.codex/prompts
cat > ~/.codex/prompts/draftpr.md << 'EOF'
변경 내용을 요약해 PR 설명 초안을 만들어 줘. 제목과 본문을 나눠서.
EOF

→ /prompts:draftpr 로 호출합니다. (인자는 $1, $2 …)

최근 Codex는 커스텀 프롬프트보다 "스킬"을 권장하는 방향입니다(5장 참고).

4-3. Antigravity CLI

커스텀 명령과 스킬이 하나로 통합돼 있습니다. .agents/skills/ 폴더에 .md 파일을 두면 파일명이 곧 명령이 됩니다.

mkdir -p .agents/skills
cat > .agents/skills/plan.md << 'EOF'
---
description: 구현 없이 단계별 계획만 세운다.
---
다음 작업의 단계별 계획만 작성한다. 코드는 쓰지 않는다.
EOF

→ 세션에서 /plan 인증 모듈 리팩터링 으로 호출합니다.

옛 방식은 폐기됐습니다 — .gemini/commands/*.toml과 /commands reload는 Gemini CLI 시절 방식이라 Antigravity CLI에서는 동작하지 않습니다. 기존 설정은 agy plugin import gemini로 옮긴 뒤 agy inspect로 확인하세요.

5장. 스킬(Skills) — 상황 보고 자동 발동하는 전문 능력

한 줄 요약: 커스텀 명령어가 내가 부르는 것이라면, 스킬은 AI가 알아서 꺼내 쓰는 것입니다.

5-1. 커스텀 명령어와 무엇이 다른가?

  • 커스텀 명령어 = 내가 /명령으로 직접 부릅니다.
  • 스킬 = AI가 상황(맥락)을 보고 알아서 꺼내 씁니다(원하면 수동 호출도 가능). 예: "엑셀 파일이 보이면 자동으로 엑셀 처리 능력을 로드".

5-2. Claude Code (가장 정돈됨)

.claude/skills/<이름>/SKILL.md 폴더 구조로 만듭니다. 2026년 기준 슬래시 명령어와 스킬이 통합되어, 모든 스킬은 /스킬이름 으로도 부를 수 있습니다.

---
name: news-cleaner
description: 뉴스 CSV의 중복·결측을 정리할 때 사용한다.
# 프론트매터로 자동 발동 여부, 메뉴 노출, 서브에이전트 실행을 제어
---
# 뉴스 CSV 정리 절차
1. 중복 기사 제거 (제목+날짜 기준)
2. 빈 본문 행 표시
...
  • 인자 치환: $ARGUMENTS, $1 $2, 스킬 폴더 경로 ${CLAUDE_SKILL_DIR}.
  • description을 잘 쓰는 게 핵심입니다. AI는 이 한 줄을 보고 "지금 이 스킬을 쓸까?"를 판단합니다 → 3-2절.

5-3. Codex / Antigravity

  • Codex: /skills 로 보고, $스킬이름 으로 직접 호출합니다. (커스텀 프롬프트의 후속 개념)
  • Antigravity: .agents/skills/<이름>/SKILL.md 폴더 구조를 씁니다. .agents/skills/lint.md 처럼 파일 하나만 둬도 /lint 로 동작합니다. 커스텀 명령과 스킬의 구분이 없습니다.

6장. 서브에이전트(Subagents) — 일을 떼어 맡기는 독립 일꾼

한 줄 요약: 큰 작업을 자기 책상(독립 문맥)을 가진 보조 일꾼에게 맡깁니다.

6-1. 왜 쓰는가?

복잡한 작업을 별도의 두뇌(독립 문맥)에게 맡기면 ① 본 대화가 깔끔하게 유지되고 ② 토큰을 아끼며 ③ 역할별 전문화가 됩니다. 예: "코드 탐색 담당", "리뷰 담당".

6-2. Claude Code

.claude/agents/ 에 정의하거나 /agents 로 관리합니다. 내장 유형은 다음과 같습니다.

  • Explore: 읽기 전용 코드베이스 탐색
  • Plan: 실행 없이 계획 수립
  • general-purpose: 범용
---
name: reviewer
description: 보안·테스트 관점으로 변경 코드를 검토한다.
tools: Read, Grep, Bash
model: haiku        # 가벼운 작업은 저렴한 모델로
---
너는 까다로운 코드 리뷰어다. 보안 취약점과 누락된 테스트를 우선 지적해라.

부르는 법은 두 가지입니다.

  • 자동 — 만들어 두기만 하면 "코드 리뷰해 줘"라고만 해도 AI가 description을 보고 이 에이전트에게 넘깁니다.
  • 직접 — "reviewer 서브에이전트로 검토해 줘"처럼 이름을 부르면 확실합니다.

자동 발동이 자꾸 안 걸리면 description을 구체적으로 고치고, 메모리 파일에 "코드 리뷰는 reviewer에게 맡긴다"를 한 줄 적으세요(3-2절).

6-3. Codex / Antigravity

  • Codex: 서브에이전트 스레드로 분기하고, 리뷰를 guardian 서브에이전트로 라우팅할 수 있습니다. /agents, 터미널에서는 codex agents 대시보드.
  • Antigravity: /agents로 서브에이전트를 관리하고 /tasks로 진행 상황을 봅니다. 병렬 실행은 사용량을 빠르게 소모하므로 무료 등급에서는 자제하세요.

선택 기준: 작업이 독립된 문맥을 필요로 하면 서브에이전트, 단순 반복이면 커스텀 명령어/스킬입니다.

7장. 훅(Hooks) — 특정 순간 자동 실행

한 줄 요약: "이 일이 끝나면 자동으로 ○○해"를 미리 등록해 둡니다.

7-1. 개념

도구 실행 전/후나 프롬프트 제출 시 같은 이벤트에 내 스크립트를 자동 실행합니다. 예: 코드 저장 후 자동 포맷팅, 비밀키가 들어가면 차단, 작업이 끝나면 알림.

7-2. Claude Code (가장 세밀)

settings.json 에 이벤트별로 등록합니다. 대표 이벤트는 PreToolUse(도구 실행 전), PostToolUse(후), UserPromptSubmit(프롬프트 제출 시), Notification, Stop 등입니다.

// .claude/settings.json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [{ "type": "command", "command": "black ." }]
      }
    ]
  }
}

→ 파일을 수정/작성할 때마다 자동으로 black(파이썬 포매터)이 실행됩니다.

7-3. Codex / Antigravity

  • Codex: /hooks 로 관리합니다. 예) userpromptsubmit 훅으로 프롬프트를 차단하거나 보강한 뒤 실행. 최근 버전에서는 훅이 비동기 실행과 MCP 도구 호출도 지원합니다.
  • Antigravity: ~/.gemini/antigravity-cli/settings.json 에서 설정합니다. 키 이름은 /config로 확인하세요.

훅은 자동으로 명령을 실행합니다. 신뢰할 수 있는 스크립트만 등록하세요.

8장. MCP — 외부 도구 연결 (Model Context Protocol)

한 줄 요약: AI를 깃허브·노션·DB 같은 외부 서비스에 연결하는 표준 전화선입니다.

8-1. 개념

MCP는 AI를 깃허브·노션·DB·브라우저·구글 워크스페이스 같은 외부 도구에 연결하는 표준 규격입니다. 한 번 연결하면 세 도구 모두 동일하게 "외부 도구를 호출"할 수 있습니다. (세 도구 다 /mcp 로 상태를 확인합니다.)

8-2. 도구별 설정 위치

도구 설정 방법
Claude Code 프로젝트의 .mcp.json, 또는 claude mcp add ... → /mcp 로 관리
OpenAI Codex ~/.codex/config.toml 의 mcp_servers, codex mcp → /mcp
Antigravity CLI 프로젝트 .agents/mcp_config.json, 전역 ~/.gemini/config/mcp_config.json → /mcp 로 관리 화면

8-3. 예시 — 깃허브 MCP 서버 (Claude 기준)

// .mcp.json
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_TOKEN": "여기에_토큰" }
    }
  }
}

→ 이후 /mcp 로 연결을 확인하고 "내 깃허브 이슈 목록 가져와" 처럼 자연어로 요청합니다.

토큰·키는 항상 환경변수나 .env에 두세요. 설정 파일을 깃허브에 올릴 땐 키가 들어 있지 않은지 반드시 확인하세요.

8-4. 플러그인 / 확장 (여러 부품을 한 번에 묶어 배포)

  • Claude: 플러그인 = 스킬+서브에이전트+명령어+훅+MCP를 한 묶음으로 설치합니다(/plugin).
  • Codex: /plugins, /apps.
  • Antigravity: agy plugin 으로 관리합니다. 구 Gemini CLI 설정을 가져올 때도 같은 명령을 씁니다(agy plugin import gemini).

9장. 더 큰 규모로 — 이름만 알아 두기

한 줄 요약: 여기부터는 필요해질 때 찾아보는 영역입니다. 지금은 "이런 게 있다"만 알면 충분합니다.

9-1. 여럿을 동시에 — 병렬

한 대화로는 조율이 벅찬 작업(대규모 리팩터링, 코드베이스 전체 감사)에 씁니다.

방식 한 줄 설명 부르는 법
서브에이전트 (6장) 일을 위임하고 결과만 보고받음 /agents
에이전트 뷰 여러 백그라운드 세션을 화면 하나에서 감독 claude agents · --bg
에이전트 팀 리드+팀원이 공유 작업목록으로 협업 팀 구성
다이내믹 워크플로 스크립트로 수십~수백 서브에이전트를 조율 /workflows · /deep-research

비용 주의: 에이전트 10개를 병렬로 돌리면 토큰(=구독 할당량·비용)도 약 10배로 나갑니다. 반드시 작은 범위로 먼저 시험하세요. Antigravity 무료 등급에서는 시도하지 마세요.

9-2. 반복과 예약 — 시간

방식 언제 동작하나 예
훅 (7장) 이벤트가 발생할 때 파일 저장 후 자동 포맷팅
/loop 내가 지켜보는 동안 타이머로 반복 /loop 5m 배포 확인
/goal 완료 조건을 채울 때까지 자기수정 반복 /loop과 짝지어 사용
백그라운드 오래 걸리는 일을 떼어서 실행 --bg · /tasks
루틴 내가 없을 때 클라우드에서 예약 실행 매일 아침 정해진 작업

/loop은 대화형 세션이라 구독 한도를 그대로 씁니다. 수천 건 반복에는 맞지 않습니다.

9-3. 수천 건 이상 — 대량 처리

  • 수천~수만 건의 독립적이고 똑같은 작업(대량 분류·라벨링·요약)은 대화형 도구가 아니라 Message Batches API로 처리합니다. 한 배치 최대 10만 건, 50% 할인, 보통 1시간 안에 끝납니다. 결과는 29일 뒤 사라지므로 받는 즉시 저장하세요.
  • 같은 입력이라도 결과는 매번 조금씩 다릅니다. Claude API에는 시드(seed)가 없고, 온도를 0으로 둬도 완전히 같지는 않습니다. 연구용이라면 여러 번 반복해 분포로 보고하고 프롬프트와 응답을 전부 기록으로 남기세요.

10장. 언제 무엇을 쓸까? — 의사결정 가이드

무엇을 자동화/확장하고 싶은가?
├── 항상 지켜야 할 규칙                → ② 메모리 파일 (CLAUDE.md / AGENTS.md)
├── 내가 직접 부르는 반복 프롬프트      → ③ 커스텀 슬래시 명령어
├── 상황 보고 '알아서' 적용될 지식      → ④ 스킬(Skill)
├── 독립 문맥이 필요한 큰 하위 작업      → ⑤ 서브에이전트
├── 여러 작업을 '동시에' 병렬로         → 다중 에이전트: 뷰·팀·워크플로 (9-1)
├── 조건 충족까지 '반복'               → /loop + /goal (9-2)
├── 내가 없을 때 '예약' 실행           → 루틴 (9-2)
├── 수천~수만 건 '대량' 처리           → Message Batches API (9-3)
├── 특정 순간 '자동으로' 실행할 동작     → ⑥ 훅(Hook)
└── 외부 서비스(깃허브·DB·노션) 연결    → ⑦ MCP
원하는 것 답 핵심 특징
매번 같은 규칙 적용 메모리 파일 세션마다 자동 로드
내가 타이밍을 정해 실행 커스텀 명령어 /명령으로 수동 호출
AI가 알아서 판단해 적용 스킬 맥락 기반 자동 발동
깨끗한 별도 작업 공간 서브에이전트 독립 문맥·도구·권한
이벤트에 반응하는 자동화 훅 트리거 기반 실행
외부 도구 호출 MCP 표준 연결 규격
여러 작업을 동시에 다중 에이전트 뷰·팀·워크플로(할당량 N배)
조건 충족까지 반복 /loop + /goal 세션 내 반복·자기수정
없을 때 예약 실행 루틴 무인 클라우드 실행

11장. 안전 수칙 & 자주 막히는 곳

안전 수칙

  1. --yolo / danger-full-access / always-proceed 는 격리 환경에서만. 승인·샌드박스를 모두 끕니다.
  2. 비밀키는 절대 코드·설정 파일에 직접 쓰지 마세요. .env + .gitignore.
  3. 큰 작업은 플랜 모드로 먼저 계획을 확인하세요 (/plan, Claude는 Shift+Tab).
  4. 훅·MCP·플러그인은 신뢰할 수 있는 출처만 등록하세요(자동 실행되기 때문입니다).
  5. 병렬 에이전트는 할당량·비용을 N배로 소모합니다. 작은 범위부터, 무인 방치 금지.
  6. 무인 자동실행(루틴·백그라운드)에 파괴적 작업(삭제·배포)을 맡기지 마세요.
  7. 배치 결과는 29일 만료 → 받는 즉시 영구 저장(DB·파일).

자주 막히는 곳

커스텀 명령이 안 뜸 파일 위치·확장자 확인. Claude .claude/commands/*.md · Codex ~/.codex/prompts/*.md · Antigravity .agents/skills/*.md

병렬 돌렸더니 할당량 순삭 동시 에이전트 수를 줄이고 소규모부터(에이전트당 별도 문맥=별도 비용)

부록. Codex만으로 진행하기

이 문서는 Claude Code를 기준으로 썼지만, OpenAI Codex만으로도 7개 부품을 모두 구현할 수 있습니다. 개념이 1:1로 대응되고 파일 이름·위치·호출 방식만 다릅니다. ChatGPT 구독자가 많다면 이 절이 곧 전체 요약본입니다.

A-2. 서브에이전트 변환 — 유일하게 형식이 다른 부품

Claude는 마크다운 프론트매터, Codex는 TOML을 씁니다. 지침 본문은 그대로 옮기면 됩니다.

--- .claude/agents/reviewer.md (Claude) ---
---
name: reviewer
description: 보안·테스트 관점으로 변경 코드를 검토한다.
tools: Read, Grep, Bash
model: haiku
---
너는 까다로운 코드 리뷰어다. 보안 취약점과 누락된 테스트를 우선 지적해라.

# .codex/agents/reviewer.toml (Codex)
name = "reviewer"
description = "보안·테스트 관점으로 변경 코드를 검토한다."
developer_instructions = """
너는 까다로운 코드 리뷰어다. 보안 취약점과 누락된 테스트를 우선 지적해라.
"""
  • 변환 규칙: name·description은 그대로, 본문은 developer_instructions의 삼중따옴표 안으로 옮깁니다.
  • 주의: tools·model 같은 세부 제어는 Codex에서 이름이 다르거나 없을 수 있습니다. codex 안에서 /help로 현재 버전을 확인하세요.
  • 변환은 AI에게 맡기세요: ".claude/agents/의 파일들을 Codex용 .codex/agents/*.toml로 변환해줘"라고 요청하면 한 번에 처리됩니다.

A-3. MCP 변환 — JSON에서 TOML로

// .mcp.json (Claude)
{
  "mcpServers": {
    "playwright": { "command": "npx", "args": ["-y", "@playwright/mcp@latest"] }
  }
}

# ~/.codex/config.toml (Codex)
[mcp_servers.playwright]
command = "npx"
args = ["-y", "@playwright/mcp@latest"]

연결 확인은 양쪽 모두 /mcp입니다. Codex는 /mcp verbose로 상세 진단이 가능합니다.

A-4. Codex에서 약한 부분과 보완책

약한 부분 보완책
변경 전 diff 미리보기 작업 후 /diff를 습관화. 중요한 파일은 눈으로 직접 확인
웹 검색이 환경에 따라 불안정 검색 MCP(Tavily·Brave 등)를 config.toml에 추가
다중·병렬 에이전트(9-1) Claude Code만큼 정돈되지 않음. 작업을 나눠 순차 실행하는 편이 안전
대량 배치(9-3) OpenAI의 Batch API를 별도로 사용. 개념은 동일

공통 안전 수칙은 그대로 적용됩니다 — --yolo·danger-full-access는 격리 환경에서만. 비밀키는 .env+.gitignore. 훅·MCP·플러그인은 신뢰할 수 있는 출처만 등록. 병렬 실행은 할당량을 N배로 소모.

핵심 — 7개 부품의 개념은 도구와 무관하게 동일합니다. 규칙은 파일로 고정하고, 반복 작업은 명령/스킬로 만들고, 큰 작업은 독립 문맥에 떼어 맡기고, 외부 도구는 MCP로 붙입니다. 이름표만 갈아 끼우면 어느 도구에서도 그대로 작동합니다.
