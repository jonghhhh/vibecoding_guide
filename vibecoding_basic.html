0부. 5분 오리엔테이션

0-1. 바이브 코딩이 뭔가요?

바이브 코딩(Vibe Coding) = 프로그래밍 언어 대신 우리말로 AI에게 시켜서 프로그램을 만드는 방식입니다.

  • for 문을 외울 필요가 없습니다. "할 일을 추가하고 지울 수 있는 웹페이지 만들어 줘" 라고 말하면 AI가 코드를 씁니다.
  • 우리가 할 일은 결과를 보고 "이렇게 고쳐 줘" 라고 대화하면서 완성도를 높이는 것입니다.
  • 즉, 나는 감독, AI는 배우입니다.

0-2. 오늘 뭘 하게 되나요? — 전체 지도

① 준비물 설치        VS Code + 터미널 + Node.js + 파이썬        (1부, 약 20분)
        ↓
② 도구 하나 설치      Claude Code / Codex / Antigravity 중 택 1  (3~5부, 약 5분)
        ↓
③ 첫 결과물          "오늘의 할 일" 웹앱을 우리말로 주문         (약 10분)
        ↓
④ 대화로 수정        "다크 모드 버튼 추가해 줘"                  (약 10분)
        ↓
⑤ 규칙 심어두기      CLAUDE.md / AGENTS.md 파일 하나            (약 5분)

세 도구를 다 설치할 필요는 없습니다. 사용법이 거의 같으므로, 계정이 있는 것 하나만 골라서 끝까지 진행하면 됩니다.

0-3. 꼭 기억할 3가지

  1. 나는 감독, AI는 배우 — 코드를 한 줄씩 쓰는 사람이 아니라, 무엇을 만들지 정하고 검수하는 사람입니다.
  2. 작게, 한 번에 한 단계 — "쇼핑몰 만들어 줘"보다 "할 일을 입력하는 칸 하나 만들어 줘"가 훨씬 잘 됩니다.
  3. AI는 가끔 틀립니다 — 그럴듯한데 틀린 답을 내놓습니다(할루시네이션). 반드시 실행해 보고 확인하세요.

1부. 준비물 설치 — 모든 도구의 출발선

세 도구 모두 ① VS Code(편집기) + ② 터미널 + ③ Node.js + ④ 파이썬 위에서 돌아갑니다. 이 넷만 깔면 나머지는 거의 같습니다.

용어가 낯설면 부록 B의 용어 사전을 먼저 훑어보세요.

1-1. VS Code 설치 (글 쓰는 창)

  1. 브라우저에서 code.visualstudio.com 접속 → Download 버튼.
  2. 내려받은 파일을 실행해 설치합니다.
  3. 메뉴를 한글로 보고 싶다면, 실행 후 왼쪽 확장(Extensions) 탭에서 Korean Language Pack을 설치합니다.

✅ 체크포인트: VS Code가 열리고 왼쪽에 아이콘 줄이 보이면 성공입니다.

1-2. 터미널 열기 (AI에게 말 거는 창구)

  • VS Code 상단 메뉴 → Terminal → New Terminal. 단축키는 Ctrl + 백틱(`)입니다.
  • 화면 아래쪽에 까만 입력창이 나타나면 성공입니다. 앞으로 여기에 명령어를 입력합니다.

✅ 체크포인트: 까만 창에 PS C:\...>(Windows) 또는 사용자이름@맥북 ~ %(macOS) 같은 글자가 보이면 준비 완료입니다.

터미널이 무섭게 생겼나요? 그냥 명령어를 받아 적는 메모장이라고 생각하세요. 이 문서의 명령어는 모두 복사해서 붙여넣고 Enter만 누르면 됩니다. 코드 블록 오른쪽 위의 복사 버튼을 쓰세요.

1-3. Node.js 설치 (엔진)

Claude Code와 Codex를 npm으로 설치할 때 필요합니다. (설치 스크립트 방식을 쓰면 없어도 되지만, 깔아 두면 두루 편합니다.)

  1. nodejs.org 접속 → LTS 버전 다운로드·설치. Windows는 설치 중 "Add to PATH" 체크를 그대로 두세요.
    주의: 설치 중 Automatically install the necessary tools 또는 Tools for Native Modules 같은 추가 개발도구 설치 옵션이 나오면 체크하지 마세요. 이 옵션을 선택하면 Python, Visual Studio Build Tools 등이 함께 설치되어 시간이 매우 오래 걸릴 수 있습니다.
  2. 설치가 끝나면 터미널을 껐다 켜고 아래를 입력합니다.
node -v
npm -v

✅ 체크포인트: v22.x.x 처럼 버전 번호가 나오면 성공입니다.

macOS에서 Homebrew를 쓴다면 brew install node 한 줄로 끝납니다. Antigravity CLI는 단일 실행파일이라 Node.js 없이도 설치됩니다(5부 참고).

1-4. 파이썬(Python) 설치

바이브 코딩으로 만든 프로그램을 실행하거나 데이터를 다루려면 파이썬이 필요합니다.

  1. 브라우저에서 python.org 접속 → 상단 Downloads.
  2. 내 컴퓨터에 맞는 버전을 내려받습니다. - Windows: 노란 버튼 "Download Python 3.x.x" 클릭. 설치 첫 화면에서 "Add python.exe to PATH" 체크가 필수입니다. 체크한 뒤 "Install Now". - macOS: "macOS 64-bit universal2 installer"를 내려받아 실행합니다.
  3. 설치 확인 — 터미널에 입력합니다.
python --version
  • macOS에서는 python3 --version으로 확인합니다.
  • 권장 버전은 3.11 이상입니다.

✅ 체크포인트: Python 3.13.x 처럼 버전이 보이면 성공입니다.

"Add to PATH"를 빠뜨렸다면 — 터미널이 python을 못 찾습니다. 설치 파일을 다시 실행해 Modify → PATH 추가를 선택하세요.

1-5. 작업 폴더 만들기 (집 짓기 전 땅 고르기)

원하는 위치에 빈 폴더를 만들고 VS Code에서 File → Open Folder로 엽니다. 터미널에서 직접 만들어도 됩니다.

mkdir my-first-vibe
cd my-first-vibe

✅ 체크포인트: VS Code 왼쪽 탐색기에 MY-FIRST-VIBE 폴더 이름이 보이고, 터미널 경로 끝이 my-first-vibe이면 성공입니다.

왜 폴더가 중요한가요? AI 코딩 도구는 터미널이 현재 열고 있는 폴더를 작업 공간으로 삼습니다. 엉뚱한 폴더에서 실행하면 엉뚱한 곳에 파일이 생깁니다. 실행 전 항상 폴더를 확인하세요.

1-6. 오늘의 공통 과제

"오늘의 할 일(To-Do) 웹앱" 할 일을 입력해 추가하고, 완료하면 체크하고, 삭제할 수 있는 한 페이지짜리 웹앱. 별도 설치 없이 브라우저로 바로 열 수 있도록 HTML 파일 하나로 만듭니다.

3·4·5부에서 같은 과제를 도구만 바꿔 만들어 봅니다. 결과물이 어떻게 다른지 비교하는 것이 목적입니다.

2부. 가상환경(.venv)과 pip — 파이썬을 쓸 때만

급하면 건너뛰어도 됩니다. 3부(첫 실습)를 먼저 해보고, 파이썬 프로그램을 만들 때 이 절로 돌아오세요. 다만 이 절만 익혀 두면 설치 관련 사고가 거의 사라집니다.

2-1. 왜 가상환경을 쓰나요?

  • 문제: 패키지를 컴퓨터 전체에 설치하면 프로젝트끼리 버전이 충돌합니다. A 프로젝트는 requests 2.28이 필요한데 B 프로젝트가 2.32로 덮어쓰는 식입니다.
  • 비유: 가상환경은 프로젝트 전용 서랍입니다. 서랍 안에만 물건을 넣으니 다른 프로젝트와 섞이지 않습니다. 프로젝트를 지울 땐 서랍째 버리면 끝입니다.
  • 결과: "내 컴퓨터에선 되는데" 문제가 크게 줄어듭니다.
  • 이 강의의 표준: 파이썬 기본 기능인 venv + pip. 추가로 배울 도구가 없습니다.

이름이 왜 .venv인가요? 관례입니다. 점(.)으로 시작해 숨김 폴더가 되고, VS Code·깃 등 대부분의 도구가 이 이름을 자동으로 알아봅니다.

2-2. 만들기 · 켜기 · 끄기

① 작업 폴더로 이동 — 가상환경은 프로젝트 폴더 안에 만듭니다.

cd my-first-vibe

② 가상환경 만들기 — 폴더 안에 .venv/가 생깁니다. 한 프로젝트에 한 번만 실행하면 됩니다.

# Windows
python -m venv .venv

# macOS / Linux
python3 -m venv .venv

③ 활성화(켜기) — 터미널을 새로 열 때마다 필요합니다.

# Windows · PowerShell (VS Code 기본 터미널)
.venv\Scripts\Activate.ps1

# Windows · 명령 프롬프트(cmd)
.venv\Scripts\activate.bat

# macOS / Linux
source .venv/bin/activate

④ 켜졌는지 확인 — 터미널 입력줄 맨 앞에 (.venv)가 붙으면 성공입니다.

(.venv) PS C:\vscode\my-first-vibe>
 ↑ 이 표시가 핵심입니다

⑤ 끄기 — 다른 프로젝트로 옮길 때.

deactivate

✅ 체크포인트: 줄 맨 앞에 (.venv)가 보이나요? 안 보이면 아직 켜지지 않은 것입니다.

2-3. pip로 패키지 설치하기

반드시 (.venv)가 켜진 상태에서 설치하세요. 그래야 서랍 안으로 들어갑니다.

pip install requests python-dotenv
명령 하는 일
pip install 패키지명 패키지 설치
pip list 지금 서랍에 뭐가 들었는지 확인
pip freeze > requirements.txt 설치 목록을 파일로 저장(버전까지 고정)
pip install -r requirements.txt 저장된 목록 그대로 재설치. 다른 컴퓨터에서 똑같은 환경 복원
pip install --upgrade 패키지명 최신 버전으로 올리기

실행 — 활성화 상태에서 그냥 python을 씁니다.

python wordcount.py

공유·백업 규칙 — .venv/ 폴더는 공유하지 않습니다(용량이 크고 OS마다 내용이 다릅니다). 대신 requirements.txt만 공유하세요. .gitignore에 .venv/와 .env를 넣어 두는 것도 잊지 마세요.

2-4. VS Code에 가상환경 연결하기

VS Code가 어느 파이썬을 쓸지 알려 줘야 자동완성·오류 표시가 맞게 동작합니다.

  1. VS Code 확장 탭에서 Python 확장(제작사 Microsoft)을 설치합니다.
  2. Ctrl+Shift+P(macOS는 Cmd+Shift+P) → Python: Select Interpreter 입력.
  3. 목록에서 .venv가 붙은 항목을 고릅니다. 보통 ('.venv': venv)로 표시됩니다.
  4. 이후 VS Code 터미널을 새로 열면 (.venv)가 자동으로 켜집니다.

2-5. 가상환경에서 자주 나는 오류

증상 원인과 해결
PowerShell에서 이 시스템에서 스크립트를 실행할 수 없으므로… Windows 스크립트 실행 정책 때문입니다. 아래 명령을 한 번 실행한 뒤 다시 활성화하세요
ModuleNotFoundError: No module named 'requests' 설치는 했는데 활성화를 안 한 상태로 실행한 경우가 대부분입니다. (.venv) 표시부터 확인
pip: command not found 파이썬 미설치 또는 PATH 누락. python -m pip install ...로 우회할 수 있습니다
설치했는데 VS Code가 빨간 줄로 표시 인터프리터 미선택. 2-4절을 다시 수행
폴더를 옮겼더니 활성화가 안 됨 .venv는 경로를 기억합니다. .venv 폴더를 지우고 2-2부터 다시 실행 
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

막히면 AI에게 그대로 물어보세요 — 오류 메시지를 복사해 붙이고 "내 OS는 Windows야. 이 오류 원인과 해결 방법을 알려줘"라고 요청하면 됩니다. 설치 문제는 AI가 가장 잘 해결하는 영역입니다.

# macOS · Linux · WSL

# Windows · PowerShell  (창 왼쪽에 PS 가 보이면 PowerShell)

REM Windows · 명령 프롬프트(CMD)  (PS 없이 C:\ 로 시작하면 CMD)

3-4. 첫 실습 — 할 일 웹앱 만들기

claude가 실행된 상태에서 우리말로 그대로 입력합니다.

초보자도 이해하기 쉽게, 할 일을 추가·완료체크·삭제할 수 있는 '오늘의 할 일' 웹앱을 만들어 줘.
조건:
1) 설치 없이 브라우저로 바로 열리도록 index.html 파일 하나로 만들 것
2) 디자인은 깔끔하고 모바일에서도 보기 좋게
3) 할 일 목록은 새로고침해도 남아 있도록 브라우저에 저장

Claude Code는 계획을 먼저 보여주고, 동의하면 index.html을 만듭니다. 파일이 생기면 더블클릭하거나 아래 명령으로 엽니다.

# macOS
open index.html
# Windows
start index.html

✅ 체크포인트: 브라우저에 할 일 입력창과 "추가" 버튼이 보이고, 실제로 항목이 추가되면 첫 바이브 코딩 성공입니다.

아래는 나올 결과물의 뼈대 예시입니다. 이런 코드가 나오는지 눈으로 확인하는 용도이며, 외울 필요는 전혀 없습니다.

<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1.0" />
  <title>오늘의 할 일</title>
  <style>
    body { font-family: sans-serif; max-width: 480px; margin: 40px auto; padding: 0 16px; }
    .done { text-decoration: line-through; color: #aaa; }
    li { display: flex; justify-content: space-between; padding: 8px 0; }
  </style>
</head>
<body>
  <h1>오늘의 할 일</h1>
  <input id="todoInput" placeholder="할 일을 입력하세요" />
  <button onclick="addTodo()">추가</button>
  <ul id="todoList"></ul>
  <script>
    // 브라우저 저장소(localStorage)에서 목록 불러오기
    let todos = JSON.parse(localStorage.getItem('todos') || '[]');
    function save() { localStorage.setItem('todos', JSON.stringify(todos)); render(); }
    function addTodo() {
      const v = document.getElementById('todoInput').value.trim();
      if (!v) return;
      todos.push({ text: v, done: false });
      document.getElementById('todoInput').value = '';
      save();
    }
    function render() {
      const ul = document.getElementById('todoList');
      ul.innerHTML = '';
      todos.forEach((t, i) => {
        const li = document.createElement('li');
        li.innerHTML = `<span class="${t.done ? 'done' : ''}"
          onclick="toggle(${i})">${t.text}</span>
          <button onclick="remove(${i})">삭제</button>`;
        ul.appendChild(li);
      });
    }
    function toggle(i) { todos[i].done = !todos[i].done; save(); }
    function remove(i) { todos.splice(i, 1); save(); }
    render();
  </script>
</body>
</html>

3-6. 두 번째 실습 — 파이썬 프로그램 만들고 실행하기

웹페이지(HTML)는 브라우저로 열어 봤습니다. 이번에는 터미널에서 돌아가는 작은 파이썬 프로그램을 만들어, AI가 코드를 쓰고 직접 실행해 결과까지 보여주는 경험을 합니다.

먼저 가상환경을 켭니다 — 2부대로 (.venv)가 켜진 상태에서 진행하세요.

claude 실행 상태에서 우리말로 요청합니다.

글을 분석해 글자 수·단어 수·문장 수를 세어 주는 간단한 파이썬 프로그램을 만들어 줘.
조건:
1) 파일 이름은 wordcount.py
2) 분석할 예시 글을 코드 안에 넣어 두고, 결과를 보기 좋게 출력
3) 초보가 읽기 쉽게 한국어 주석을 충분히 달 것
4) 표준 라이브러리만 사용(추가 설치 없이 실행되게)
그리고 그 프로그램을 실행해서 결과까지 보여줘.

Claude가 wordcount.py를 만들고 직접 실행해 결과를 보여줍니다. 만들어질 코드의 예시입니다.

# 분석할 글 (이 부분만 바꾸면 다른 글도 분석됩니다)
text = "오늘 시청에서 기자회견이 열렸다. 시장은 내년 예산을 발표했다. 질문도 이어졌다."

# 글자 수 (공백 포함 / 공백 제외)
char_with_space = len(text)
char_no_space = len(text.replace(" ", ""))

# 단어 수 (공백 기준으로 나눠 셉니다)
word_count = len(text.split())

# 문장 수 (마침표·물음표·느낌표 개수로 단순 계산)
sentence_count = text.count(".") + text.count("?") + text.count("!")

print("글자 수(공백 포함):", char_with_space)
print("글자 수(공백 제외):", char_no_space)
print("단어 수:", word_count)
print("문장 수:", sentence_count)

직접 실행해 보려면 터미널에 입력합니다.

python wordcount.py

✅ 체크포인트: 터미널에 글자 수(공백 포함): 43 처럼 숫자가 출력되면 성공입니다.

외부 패키지가 필요한 프로그램이라면 — (.venv)가 켜진 상태에서 pip install로 먼저 설치하세요. AI에게 "필요한 패키지를 pip install로 설치하고 requirements.txt에도 추가해 줘"라고 요청하면 한 번에 처리됩니다.

웹앱 때와 똑같이, 결과를 보고 말로 고치면 됩니다.

평균 문장 길이(공백 제외 글자 수 ÷ 문장 수)도 함께 출력해 줘.

HTML(웹페이지)과 파이썬(프로그램) 두 가지를 만들어 보면, 바이브 코딩이 웹뿐 아니라 일반 프로그램에도 똑같이 통한다는 걸 알 수 있습니다.

5-3. 설치와 로그인

Antigravity CLI는 npm 패키지가 아닙니다. 설치 스크립트로만 깝니다. Node.js도 필요 없습니다.

# macOS · Linux
curl -fsSL https://antigravity.google/cli/install.sh | bash

# Windows · PowerShell
irm https://antigravity.google/cli/install.ps1 | iex

REM Windows · 명령 프롬프트(CMD)
curl -fsSL https://antigravity.google/cli/install.cmd -o install.cmd && install.cmd && del install.cmd

설치 스크립트가 OS와 CPU 종류를 알아서 판별해 실행파일을 내려받고, 체크섬을 확인한 뒤 ~/.local/bin/agy에 넣어 줍니다. 이후 업데이트도 자동입니다.

실행과 로그인 — 작업 폴더에서 agy를 입력하면 브라우저가 열리며 구글 계정 인증을 진행합니다.

agy

동작 확인 — 한 줄 질문으로 바로 테스트해 볼 수 있습니다.

agy -p "이 폴더에 뭐가 들어 있는지 요약해줘"

✅ 체크포인트: 폴더 내용 요약이 출력되면 성공입니다.

기존 Gemini CLI 사용자 — 설정을 옮기는 마법사가 있습니다. 첫 실행 때 가져오기를 수락하면 MCP 서버 등록·허용 명령어·키바인딩이 자동으로 넘어옵니다. 수동으로 하려면 아래 명령을 쓰고 agy inspect로 결과를 확인하세요.

agy plugin import gemini
agy inspect

5-5. 무료 한도 주의 (강의 전 확인 필수)

"무료로 넉넉하게"는 옛말입니다. 무료 등급은 하루 20회 안팎의 에이전트 요청으로 제한됩니다(5시간 단위로 조금씩 회복). 실습 도중 한도에 걸려 멈추는 사례가 흔합니다. 강의 실습의 기본 도구로는 권장하지 않습니다. 유료(Pro / AI Ultra)를 쓰거나, 시연·보조용으로만 사용하세요. 유료 등급도 2026년 3월부터 주 단위 한도로 바뀌어, 한도를 다 쓰면 최대 일주일간 잠길 수 있습니다.

  • 서브에이전트 병렬 실행은 사용량을 아주 빠르게 소모합니다. 입문 단계에서는 쓰지 마세요.
  • /usage(또는 /quota)로 남은 양을 확인하는 습관이 필요합니다.
  • 추가 크레딧 구매도 가능하지만 입문 실습에 필요한 수준은 아닙니다.

6-2. 어떤 도구든 통하는 원칙 5가지

  1. 작게 쪼개서 시킬 것 — "앱 전체"가 아니라 "기능 하나"씩.
  2. 조건을 구체적으로 적을 것 — 파일 형식, 디자인, 저장 방식까지 명시.
  3. 계획을 먼저 보고 승인할 것 — 실행 전에 무엇을 할지 확인.
  4. 항상 실행해서 확인할 것 — AI는 틀릴 수 있습니다.
  5. 규칙은 .md 파일로 고정할 것 — CLAUDE.md / AGENTS.md.

  • --yolo·danger-full-access 금지 — 승인과 샌드박스를 모두 끕니다. 강의 환경에서는 절대 쓰지 마세요.
  • 웹 검색이 환경에 따라 약합니다 — 근거 검색이 필요한 작업은 결과를 반드시 링크로 확인하세요. 부족하면 검색 MCP(Tavily·Brave 등)를 붙이는 방법도 있습니다(심화 가이드 참고).
  • 명령·설정이 자주 바뀝니다 — codex 안에서 /help로 현재 버전의 명령 목록을 먼저 확인하세요.

핵심 — 도구가 달라져도 바이브 코딩의 사이클은 같습니다. 말로 요청 → 계획 확인 → 실행 → 결과 검수 → 규칙 파일로 고정. 이 흐름만 몸에 익히면 어느 도구로 옮겨도 30분이면 적응할 수 있습니다.
